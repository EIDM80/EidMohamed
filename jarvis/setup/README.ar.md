# التثبيت — ويندوز 11 على RTX 4080

ثلاث خدمات فقط: Ollama + Open WebUI + Open WebUI Computer. لا تضف رابعة قبل أن تستخدم
هذه أسبوعين. الخطة الكاملة للجهاز في [`../hardware-plan.ar.md`](../hardware-plan.ar.md).

**تبسيط مهم لويندوز:** يعمل Ollama **أصلياً** على ويندوز فيصل إلى الـ4080 مباشرة — بلا
تمرير كرت عبر WSL2 وبلا nvidia-container-toolkit. وOpen WebUI مجرد واجهة ويب لا تلمس كرت
الشاشة، فيكفيها Docker عادي. هذا يحذف أكثر خطوة يتعثّر فيها الناس.

## الطريق السريع: أمر واحد

إن أردت تخطّي الخطوات اليدوية كلها، شغّل هذا (**بصلاحيات مسؤول**) من داخل مجلد `setup`:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\bootstrap.ps1
```

يثبّت Ollama وDocker وPython عبر winget إن كانت ناقصة، ويضبط المتغيّرات، ويضيف قاعدة جدار
الحماية، وينزّل النموذجين، ويولّد `.env` بمفتاح سري، ويشغّل Open WebUI. آمن لإعادة التشغيل:
كل خطوة تتحقّق قبل أن تنفّذ.

**نقطة توقّف واحدة متوقّعة:** إن لم يكن Docker Desktop مثبّتاً، سيثبّته ثم يطلب منك إعادة
تشغيل الجهاز وفتحه مرة واحدة يدوياً، ثم تعيد تشغيل السكربت — وسيتخطّى كل ما أنجزه.

أما إن أردت أن تفهم كل خطوة وتنفّذها بنفسك، فتابع أدناه.

## قبل أن تبدأ

```powershell
.\jarvis.ps1 check
```

يفحص كرت الشاشة وOllama وDocker وPython وإعدادات البيئة، ويقول لك بالضبط ما الناقص.

## 1. تعريف كرت الشاشة

ثبّت أحدث تعريف NVIDIA، ثم تحقّق:

```powershell
nvidia-smi
```

يجب أن ترى `NVIDIA GeForce RTX 4080` و`16376 MiB` تقريباً.

## 2. Ollama

نزّله من [ollama.com/download/windows](https://ollama.com/download/windows) وثبّته، ثم
اضبط متغيّرين — **افتح PowerShell كمسؤول**:

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_HOST","0.0.0.0","Machine")
[Environment]::SetEnvironmentVariable("OLLAMA_KEEP_ALIVE","60s","Machine")
```

ثم أغلق Ollama من شريط المهام وأعد تشغيله ليقرأ الإعدادات الجديدة.

- `OLLAMA_HOST=0.0.0.0` — بدونه لن تستطيع حاوية Open WebUI الوصول إلى Ollama إطلاقاً.
- `OLLAMA_KEEP_ALIVE=60s` — يفرّغ النموذج من الـVRAM بعد دقيقة خمول. **هذا هو السطر الذي
  يجعل قاعدة الـ16 جيجابايت قابلة للحياة**: بدونه يبقى النموذج محتلاً 9 جيجابايت فلا يبقى
  مكان لتوليد الصور.

> ⚠️ **ملاحظة أمنية:** ضبط `0.0.0.0` يجعل Ollama يستمع على **كل** الشبكات لا على جهازك
> فقط — أي أن أي جهاز على شبكة الواي فاي يستطيع استخدام نموذجك. أضف قاعدة جدار حماية
> (كمسؤول) تمنع الاتصال الخارجي:
>
> ```powershell
> New-NetFirewallRule -DisplayName "Block Ollama from LAN" -Direction Inbound `
>   -LocalPort 11434 -Protocol TCP -Action Block -Profile Public,Private
> ```
>
> تبقى حاويات Docker قادرة على الوصول لأنها تمرّ عبر الواجهة الداخلية.

ثم نزّل النموذجين:

```powershell
ollama pull qwen3:14b   # ~9 ج.ب — النموذج الأساسي، ~49 توكن/ثانية
ollama pull qwen3:8b    # ~5 ج.ب — للجلسات كثيفة التوليد حين تحتاج VRAM للصور
```

اختبره: `ollama run qwen3:14b "اكتب جملة واحدة"`

## 3. Open WebUI

ثبّت [Docker Desktop](https://docs.docker.com/desktop/install/windows-install/) بواجهة
WSL2، ثم من هذا المجلد:

```powershell
Copy-Item .env.example .env
```

افتح `.env` وضع قيمة طويلة عشوائية في `WEBUI_SECRET_KEY` — ولّدها بـ:

```powershell
[guid]::NewGuid().ToString() + [guid]::NewGuid().ToString()
```

ثم شغّل:

```powershell
.\jarvis.ps1 start
```

افتح <http://localhost:3000>. أول حساب تسجّله يصير حساب المسؤول. اختر `qwen3:14b` من قائمة
النماذج في الأعلى.

## 4. Open WebUI Computer (اختياري لكنه الأهم)

هذا ما يحوّله من شات بوت إلى وكيل يعمل على حاسوبك. يحتاج **Python 3.11 أو 3.12**:

```powershell
pip install cptr
cptr run
```

اقرأ الرابط الذي يطبعه عند التشغيل وافتحه (Open WebUI عندك على المنفذ 3000 حتى لا يتعارض
مع منفذ cptr الافتراضي). يعطيك ملفات وطرفية ومحرّراً وgit ومتصفحاً، مع ضوابط موافقة لكل
محادثة — **أبقِ الموافقة مفعّلة** حتى تثق بسلوكه.

## الاستخدام اليومي

| الأمر | ماذا يفعل |
|---|---|
| `.\jarvis.ps1 start` | يشغّل Ollama وOpen WebUI |
| `.\jarvis.ps1 status` | ما الذي يعمل، وكم VRAM مستهلكة الآن |
| `.\jarvis.ps1 stop` | يوقف كل شيء **ويفرّغ النماذج من الـVRAM** |
| `.\jarvis.ps1 check` | يفحص المتطلبات والإعدادات |

الخدمات **لا تبدأ مع إقلاع ويندوز** عمداً — لأن هذا جهازك اليومي، ولا داعي لأن تلتهم
الموارد وأنت تعمل. شغّلها عند الحاجة، وأوقفها قبل الألعاب أو المونتاج.

`status` يحذّرك إذا تجاوز استهلاك الـVRAM 70% — وهي العتبة التي لن يتّسع بعدها توليد الصور.

## الإحاطة الصباحية

بما أن هذا جهازك اليومي وقد يكون مغلقاً في السادسة صباحاً، فالإحاطة اليومية تُجدوَل في
**السحابة** عبر `/schedule` في Claude، لا عبر cron محلي. أمر الإحاطة جاهز في
[`../README.ar.md`](../README.ar.md#أمر-الإحاطة-البرومبت).

الأدوار الصحيحة: المحلي يتولى ما هو خاص ودائم وكثيف الحجم؛ والسحابة تتولى ما يحتاج تفكيراً
ويجب أن يعمل والجهاز مغلق.

## حين يتعطّل شيء

| العَرَض | السبب |
|---|---|
| Open WebUI لا يرى أي نموذج | `OLLAMA_HOST` ليس `0.0.0.0`، أو لم تُعد تشغيل Ollama بعد ضبطه |
| "connection refused" داخل الحاوية | Ollama متوقف — شغّله بـ `ollama serve` |
| بطء شديد أو تجمّد | النموذج تجاوز الـVRAM وارتدّ إلى المعالج. راجع `.\jarvis.ps1 status` وانزل إلى `qwen3:8b` |
| توليد الصور يفشل بنفاد الذاكرة | نموذج لغوي ما زال محمّلاً. `.\jarvis.ps1 stop` ثم أعد التوليد |
| `cptr` لا يعمل | نسخة Python — يحتاج 3.11 أو 3.12 |
